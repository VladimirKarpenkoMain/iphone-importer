# Галерея с превью и выбор отдельных файлов

Дополнение к `2026-10-07-iphone-importer-design.md`: снимает из «Вне объёма» пункты «превью» и
«выбор отдельных файлов». Остальное (журнал, `.part` → rename, раскладка по дням) не меняется.

## Цель

- Отобрать часть новых файлов перед импортом (снять галочки со скриншотов, дублей).
- Найти и докопировать конкретные файлы, которые уже есть в журнале, — вместо «Скопировать всё заново».

Главный сценарий «подключил → Импортировать N» остаётся в один клик; галерея — отдельный режим.
Типичный объём телефона — 2 000–20 000 файлов.

## Источник превью (проверено на iPhone)

iOS хранит готовую JPEG-миниатюру для каждого фото и видео:
`/PhotoData/Thumbnails/V2<путь в DCIM>/5005.JPG`, например
`/PhotoData/Thumbnails/V2/DCIM/109APPLE/IMG_9399.HEIC/5005.JPG`. Доступна через тот же AFC.

- Размер ~45 КБ, ~360×480 (видео 326×580). Других размеров нет — это и плитка, и увеличение.
- Нет миниатюры у видеочасти Live Photo (`IMG_4020.MOV` рядом с `IMG_4020.HEIC`): в выборке из
  302 файлов отсутствовали 42, все — такие MOV. Решается объединением пары в одну плитку.
- Декодирование — крейт `image` только с `jpeg` (чистый Rust): `.exe` по-прежнему тянет
  только системные DLL. HEIC/видео сами не декодируем.

Отвергнуто: декодировать оригиналы (HEIC без libheif невозможен, 3–5 МБ на плитку);
миниатюры Windows Shell (нужны локальные файлы и HEIF-расширение).

## Данные (`import.rs`)

```rust
pub struct Item { pub files: Vec<RemoteFile>, pub imported: bool }
pub fn group(files: &[RemoteFile], journal: &Journal) -> Vec<Item>
```

- Плитка = один файл или пара Live Photo: фото + `.MOV` с тем же путём без расширения
  (сравнение без учёта регистра). Фото в паре первое; ключ плитки и миниатюра — `files[0]`.
- `.MOV` без фото-пары — обычная плитка-видео.
- `imported` — **все** файлы плитки есть в журнале. Пара, импортированная наполовину, считается
  новой и импортируется целиком (уже скопированная половина получит имя `(n)` — редкий случай,
  принимаем).
- Порядок — по пути (`/DCIM/100APPLE/…`, ≈ хронология).
- `select(.., all)` удаляется: список файлов на импорт теперь собирает GUI.

## Протокол worker ↔ GUI (`worker.rs`)

- `Phone::Ready { udid, items: Vec<Item> }` вместо `new/all: Summary`. Счётчики главного экрана
  GUI считает `summarize` по файлам неимпортированных плиток.
- `Cmd::Import(Vec<RemoteFile>)` вместо `Import { all }`. `import_now` получает готовый список;
  проверка места, `clean_parts`, `run` — как раньше.
- `Cmd::Thumbs(Vec<String>)` — пути (`files[0].path`) видимых плиток, которых нет в кеше GUI.
  Новая команда **заменяет** очередь целиком: быстрая прокрутка не копит хвост.
- `Msg::Thumb { path, jpeg: Option<Vec<u8>> }`; `None` — миниатюры нет/не прочиталась.
- Цикл: пока очередь миниатюр не пуста — читает одну миниатюру за итерацию и команды через
  `try_recv`; пуста — `recv_timeout(2 s)` как сейчас. Проверка `still_connected` — не чаще раза
  в 2 с при любой очереди. После импорта и при потере телефона очередь очищается.

## Устройство (`device.rs`)

`Device::thumbnail(&RemoteFile) -> Option<Vec<u8>>` — читает
`/PhotoData/Thumbnails/V2{path}/5005.JPG` целиком, закрывает хэндл. Любая ошибка → `None`
(пропажу телефона ловит `still_connected`).

## Интерфейс (`main.rs`)

**Главный экран** — как сейчас, но ссылка «Скопировать всё заново…» и подтверждение `confirm_all`
заменены ссылкой «Выбрать файлы…» (активна при `Ready` и без импорта).

**Экран галереи** (`screen: Main | Gallery`):

- Шапка: «← Назад», переключатель «Новые | Все», «Выбрать все» / «Снять все» (действуют на
  показанные плитки).
- Сетка квадратных плиток ~120 px, число колонок — по ширине окна; `ScrollArea::show_rows`
  рисует только видимые строки. Для видимых плиток без миниатюры отправляется `Cmd::Thumbs`
  (только когда набор видимых изменился).
- Плитка: миниатюра, обрезанная по центру до квадрата; кружок выбора в правом верхнем углу
  (синий с ✓, если выбрана); метка «LIVE» для пар, «▶» для видео; импортированные приглушены и
  помечены «✓ импортировано». Пока миниатюры нет — серая плитка; если `None` — серая с
  расширением и размером.
- Клик — переключает выбор. Двойной клик — увеличение: модальное окно с миниатюрой до 480 px,
  именами файлов, размером и состоянием; ←/→ — соседняя плитка, Пробел — выбор, Esc/клик вне —
  закрыть.
- Низ: «Выбрано N · X ГБ» и кнопка «Импортировать N» (N — число файлов). Нажатие → `start(files)`
  → возврат на главный экран, где идёт прогресс. Без подтверждения: выбор уже явный.

**Состояние выбора:** `HashSet<String>` по ключу плитки. При входе в галерею — все
неимпортированные. На новый `Ready` (смена папки, пересканирование) — пересечение с
существующими ключами. Телефон пропал (любой `Phone` кроме `Ready`/`Scanning`) — возврат на
главный экран.

**Кеш миниатюр:** ключ → `{ jpeg: Vec<u8>, tex: TextureHandle }`, текстура уменьшена до ~160 px
по длинной стороне (`image::imageops::thumbnail`), увеличение декодирует `jpeg` заново.
Не больше 1 500 записей, вытесняется давно не показанная (~1 500 × ~150 КБ ≈ 225 МБ).
`None` запоминается, чтобы не запрашивать повторно. Кеш живёт до смены телефона.
Дискового кеша нет.

## Ошибки

- Нет/битая миниатюра → плитка-заглушка; выбор и импорт работают.
- Журнал не открылся при `Ready` → `Msg::Error`, как сейчас.
- Импорт выбранных — та же семантика `run`: обрыв/отмена/диск останавливают, ошибка файла —
  пропуск. Повторный импорт файла, уже записанного в журнал, добавляет дубль строки (безвредно,
  как раньше у «всё заново»).

## Тесты

- `import::group`: пара Live Photo (в т.ч. разный регистр расширений), MOV без пары, одиночное
  фото, `imported` для пары целиком / наполовину, сортировка.
- Кеш миниатюр — `Cache<V>` (обобщён по значению, в приложении `V = Thumb`, в тесте `V = ()`):
  вытеснение давно не показанной записи при превышении лимита.
- `App`: вход в галерею выбирает все новые; `Ready` сохраняет пересечение выбора; импорт из
  галереи шлёт `Cmd::Import` с файлами выбранных плиток (обе половины пары); пропажа телефона
  возвращает на главный экран; существующие тесты `start`/`drain` адаптируются.
- Аппаратный `#[ignore]`-тест: `thumbnail` для первого файла списка возвращает JPEG
  (начинается с `FF D8`).

## Зависимости

`image = { version = "0.25", default-features = false, features = ["jpeg"] }`. После сборки —
проверка `objdump`, что добавились только системные DLL.
